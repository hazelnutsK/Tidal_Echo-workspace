# API 身体主动来电

API 的常规聊天、欲望事件和主动联系均可使用本地 `call` 工具。默认可用，受原有 `tools_enabled` 总开关控制。不新增主动联系中的拨号提示，不规定必须拨打。

主动联系保留普通聊天的工具定义及稳定前缀缓存边界；需要工具时执行有限轮工具循环，每次执行前检查窗口、会话版本和当前身体是否仍匹配。缓存保活模式仍不执行工具。

`call` 向 relay 发送带 `api_session` 和唯一 `call_request_id` 的来电。同轮重复调用、模型 fallback 以及发送超时均不会自动重拨；relay 也会根据 request id 去重，并在已有来电或通话时拒绝新请求。发起来电后这一轮停止，接听事件才触发开场白。

relay 将来电状态持久化为 ringing / accepted / missed / ended。120 秒未接听会反馈一次未接事件，拒接和挂断同样反馈到原窗口。事件进入后续 API 上下文。测试使用临时 SQLite 与假模型，不会真实拨号。

现有 iOS 在发起来电的窗口中即可使用 API 来电。新客户端补上接听前切回原窗口、显式传递来电 id 和超时停止响铃；需重新构建安装。旧客户端跨窗口接听会被后端拒绝，避免把通话接到错误的身体。PWA 补上来电 id、拒接上报和过期过滤。

当前个人签名的远程 VoIP 推送限制仍然存在；本改动不新增 APNs/PushKit 权限。Windows 上已验证 Python 测试和网页脚本语法，iOS 需在 macOS/Xcode 构建验证。
