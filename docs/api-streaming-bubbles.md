# API 短聊：边生成边分段

「聊天节奏 → 短聊」现在也适用于 API 的 `reply_delta` 流式回复。模型输出一个空行时，上一段立即保存成独立消息，下一段继续流式显示。单次换行不拆气泡；代码围栏内部的空行不拆。长聊和思考流保持原有行为。

实现位于 `backend/app.py` 和 `backend/stream_paragraphs.py`，沿用现有客户端协议。普通分段和思考块排序无需重新打包 iOS 或更新 PWA。iOS 源码同时补了 `done` 事件处理：极少数最终撤回草稿（静默或卡片合并）的场景，彻底清理草稿需要安装包含此修复的新包。

- 每段使用独立的 `stream_id`，并以 `stream_parent` 关联同一轮回复。
- 已完成段落在历史记录里；SSE 重连仅重发当前段落的草稿。
- 第一个正文片段到达时先保存思考块，后续工具轮的思考更新同一条记录，固定在正文气泡前。重连返回这条思考记录，不再另建尾部思考草稿。
- 最终 `final_text` 为准，修正工具多轮续写或备用模型带来的文本差异，复用已有消息 ID，避免整篇重复发送。
- 本轮 API 用量只写到最后一个气泡，通知和欲望状态更新每轮仅执行一次。
- 每轮开始时固定长聊/短聊和段尾句号设置，切换设置影响下一轮。
- 语音、文件及结构化卡片保持完整；如果卡片标记在后半段才出现，最终会合并回一条完整消息。
- 模型没有输出空行时仍为一条气泡，不按句号强行切句。后台主动消息本身先缓冲生成，因此在定稿时分段。

离线回归：在 `backend/` 运行 `.venv/Scripts/python.exe -m unittest test_stream_paragraphs -v`。测试使用临时 SQLite，不读取私密配置、不调用模型、不向真实聊天发送消息。
