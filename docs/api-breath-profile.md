# API 呼吸配比

网页设置 → 模型 → **API 呼吸配比**。默认启用：钉选与核心 3 条、高分 3 条、近期 8 条。每类可设 0–20 条，启用时至少一类非零。保存后下一次普通 `breath()` 生效，已有查阅记录不会被改写。

```json
{"breath_profile":{"enabled":true,"pinned":3,"score":3,"recent":8}}
```

配置通过已有的已鉴权 `/app/loop_config` 转发至 API loop。关闭开关恢复 OB 原有呼吸。只改变 API 无参数 `breath()`，不改变桌面 OB、`breath_search`、`breath_advanced` 或带参数的旧调用。

## 选取与长度

- 钉选与核心：pinned、protected 或 permanent，优先重要性和创建时间。
- 近期：其他记忆按创建时间倒序，允许已解决的事件。创建时间只是事件时间的近似，不使用容易被查阅刷新的 last_active。
- 高分：其他未解决记忆按分数排序；先满足近期配额，再选择未重复的高分记忆。
- 三类去重。过滤 dont_surface、anchor、删除和归档状态，以及 feel、plan、letter、self、i 等私密类别；候选列表只作索引，每条读取详情重新核实标记。
- 条数是上限。长度上限取工具结果上限和“本窗查阅记忆字数预算”中较小者，并预留包装空间。按条数比例为三类预留正文空间，剩余空间优先让近期借用。
- 保留完整的单条正文及内部链接；整条过长时跳过并列出未载入的 id，不把列表预览当正文。结果显示各类实际条数/请求条数。候选不足不会拿其他类别冒充补足。
- 配额呼吸进入本窗查阅存档后，在总预算允许时完整回放，不再套用普通单次查阅的 6000 字节选上限。后续新增查阅仍可能挤出较早记录，可用 `memory_read` 回读。

## 运行与限制

不需要重新部署 OB；更新 Tidal relay 和 API loop 即可。通过已有 OB 网页只读代理取列表与正文，不主动触碰记忆激活时间，不额外调用摘要模型。代理的列表缓存可能短暂滞后；每次详情检查仍使用最新标记。

每批最多 4 个详情请求、最多检查 80 个候选，整次取数限时 25 秒。旧 relay 缺少完整标记、网络失败或超时会明确标注并回退原版 OB 呼吸；冷列表缓存尤其可能触发回退。候选检查达到上限时，实际条数可能不足。

设置本身不会重写已有交接和查阅；新呼吸结果作为一次新的工具查阅保存，沿用本窗上下文预算和缓存行为。启用或关闭自定义配比会切换工具说明，下一次请求的缓存命中可能受影响；只调条数不改工具说明。

## 验证

`backend/.venv/Scripts/python.exe -X utf8 -m unittest discover -s examples -p "test_*.py"`

测试使用虚构资料与临时数据库，覆盖分路配额、去重、近期排序、详情策略过滤、整条正文预算、原版回退和后续轮次回放，不发送消息或调用模型。
